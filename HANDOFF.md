## 3. The research (done, published)

**Model:** `openai/whisper-small` + LoRA (r=32, α=64, q_proj/v_proj, 1.44% params) trained on TORGO (8 dysarthric speakers). Adapter at `JJaysz/cohear-whisper-small-dysarthric`. Merged weights at `JJaysz/cohear-whisper-small-merged`. Core ML export for iOS at `JJaysz/cohear-whisperkit`, variant `JJaysz_cohear-whisper-small-merged`.

**Headline results** (`results/comparison.csv`, `by_severity.csv`): WER on severe speaker M04 84.4% → 34.6%. Pooled 8-speaker adapter beat per-speaker adapters. Full write-up: `outreach/CoHear_Research_Writeup.md/.pdf`.

**TORGO permission:** Frank Rudzicz (TORGO maintainer, Dalhousie) approved publishing adapter *and* merged weights, conditioned on not redistributing TORGO data. `.gitignore` blocks `TORGO_datasets/`. **Never commit TORGO. Never `git add -A` without checking `git status` first.** The `.PHN` phone labels were hand-done in Wavesurfer by an SLP (personal communication from Frank).

**Phonological layer — cut.** A partner (Melodie) built an Allosaurus-based phone-level layer on branch `melodie-phonetics`. Calibration experiment (`scripts/phone_calibration.py`, `results/PHONE_CALIBRATION.md`, `results/LAYER_DECISION.md`) showed the phone recognizer's error rate on dysarthric speech (7.9%) barely separates from its noise floor on control speech (2.2%), only 19.6% of dysarthric clips have any phone error, and homophones ("write"→"right") defeat it. Decision: not in the live pipeline; keep as a clinical instrument. Nick removed Melodie from outward-facing docs. `outreach/CoHear_Research_Brief.md` and `CoHear_Writeup_forResearchers.md` still credit her — **delete them.**

**Demo:** Hugging Face Space (Gradio, CPU basic, requires HF PRO). Code in `space/app.py`. Lazy-loads model; dev mode disabled. Slow cold start (~1–2 min) is expected.

## 5. The iOS app — current state

**Stack:** SwiftUI, iOS 17+, WhisperKit 0.18 (on-device Whisper), AVAudioEngine + energy VAD, AVSpeechSynthesizer for Speak, optional Apple Foundation Models cleanup on iOS 26 devices that have Apple Intelligence (Nick's phone doesn't, so `Clarifier` falls back to raw text). Project generated by XcodeGen from `ios/project.yml` — **edit `project.yml`, never the `.xcodeproj`**, then `cd ios && xcodegen`.

**Files:** `ios/CoHear/` — `Models/SessionStore.swift` (all state), `Models/Utterance.swift`, `Services/{Transcriber,AudioRecorder,VoiceProfile,Clarifier,Speaker}.swift`, `Views/{RootView,ShowView,EditView,SettingsView,ModelSetupView,Theme}.swift`. Docs: `ios/CLAUDE.md` (rules), `BUILD.md`, `DESIGN_DECISIONS.md`, `APP_STORE_CHECKLIST.md`, `PUBLISH.md`, `DEVELOPER_ACCOUNT.md`.

**Design rules (non-negotiable, from `DESIGN_DECISIONS.md`):** speaker is the primary user; nothing is shown to others until the speaker taps Show; 64pt minimum targets; text ≥ ~22pt scaling with user setting; no gestures (no swipe/drag/long-press); nothing auto-dismisses; no swipe-to-delete; other people's voices are *dimmed, never deleted* ("keep my transcript clean").

**Voice filter:** `VoiceProfile.swift` fingerprints the speaker (median pitch, octave-folded, + 8 Goertzel spectral bands), learns from the first 3 utterances, adaptive tolerance from the speaker's own spread. Three states: `own / uncertain / other`. It was misclassifying Nick's own dysarthric speech; the adaptive rewrite fixed it. If it regresses, tune `minTolerance`/`clearMargin` in that file, not the weights.

**Mic:** energy VAD with clamped noise floor (`maxNoiseFloor 0.02`) because the floor was chasing the voice upward. Level meter is the debug tool.

**Model on device:** confirmed — console prints `[CoHear] loaded model: JJaysz_cohear-whisper-small-merged`. `Transcriber.candidates = [.cohear, .stock]` falls back to stock small.en if download fails.

**Apple Developer:** dad's paid account (Ming Lei), Team ID `B727X6U62V`, bundle `com.leifamily.cohear.CoHear` (registered manually at developer.apple.com — Xcode's auto-register failed). App Store Connect app exists, currently named "CoHear speechClarity" (should be renamed to "CoHear" or "CoHear: Speech Clarity" before submit). Build **1.0 (1)** uploaded Sep 19, processed, "Ready to Submit" — **but it's the old bland UI.**

## 8. Gotchas that cost time before

- `.git/index.lock` gets left behind by sandboxed tools — `rm -f .git/index.lock`.
- `claude` CLI lives in `~/.local/bin`; add to PATH.
- iPhone pairing: if "pairing is in progress" hangs, unpair in Xcode Devices, reset Location & Privacy on phone, restart both.
- Developer Mode on the phone only appears after a first install attempt.
- whisperkittools prints `FAILED (errors=1)` after a successful conversion — that's its post-conversion validation needing network; the `.mlmodelc` folders are fine. `scripts/convert_whisperkit.sh` checks for them.
- `.allowBluetooth` is deprecated → `.allowBluetoothHFP`.
- The HF Space needs PRO for CPU basic; ZeroGPU fails at adapter load unless `torch_device="cpu"`.
- Speaker (TTS) is a separate ObservableObject; `SessionStore` forwards its `objectWillChange` so Speak/Stop re-renders.
